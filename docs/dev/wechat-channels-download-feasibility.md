# 视频号下载可行性分析

## 结论

普通视频号分享链接可在 NovaCaption 内完成“粘贴即下载”。当前实现采用腾讯元宝
Cookie 直解析方案，不依赖本地代理、根证书、微信客户端注入或额外伴侣进程。

## 解析链路

1. 识别 `weixin.qq.com/sph/...` 分享链接。
2. 从 `AppData/cookies.txt` 读取且仅读取 `.tencent.com` 与
   `yuanbao.tencent.com` Cookie。
3. 请求腾讯元宝 `get_parse_result`，取得临时 `token` 与 `eid`。
4. 请求视频号公开预览页 `get_feed_info`，优先选择 H.264 视频地址。
5. 从媒体 CDN 流式写入 `.part` 文件，完成后原子重命名为 `.mp4`。

元宝 Cookie 只用于第一步解析请求，不会转发给视频号详情接口或媒体 CDN。

## 可行性与边界

- 普通、公开且仍可播放的视频：可行。
- 图集、直播和部分直播回放：当前不支持。
- 私密、已删除、地区或账号受限内容：取决于腾讯侧权限。
- 腾讯元宝 Cookie 会过期，需要用户重新登录并读取。
- 两个网页接口都不是稳定的公开 API，字段或鉴权变更时需要维护。

## 方案对比

| 方案 | 用户成本 | 安全影响 | 适用性 |
| --- | --- | --- | --- |
| 腾讯元宝 Cookie 直解析 | 登录一次，之后粘贴即下载 | Cookie 仅保存在本机 | 普通分享视频，当前采用 |
| 根证书 + 系统代理抓包 | 高 | 可检查设备 HTTPS 流量 | 不纳入 NovaCaption |
| 公开第三方解析站 | 低 | 链接和访问记录交给第三方 | 稳定性与隐私不可控，不采用 |
| 仅使用 yt-dlp | 低 | 低 | 目前没有可用的视频号 extractor |

## 维护原则

- 不记录 Cookie、临时 token 或完整媒体 URL。
- Cookie 导入按域过滤，并与其他平台 Cookie 原子合并。
- 所有失败都保留 `.part` 清理和可操作的中文提示。
- 解析层保持独立，未来 yt-dlp 官方支持后可直接替换实现。
